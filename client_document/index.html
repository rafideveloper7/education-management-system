System Specification & Architecture

EduOS — Education Management System

Complete Functional Requirements & 36 Canonical Modules Specification

The system is a complete digital operating platform for an educational institution consisting of:

Public Website
Public Authentication
Admin Panel
Teacher Panel
Student Panel
Parent Panel
Central Communication System
Central Notification System
Dynamic Website Management

Key Architectural Rule: The four academic panels (Admin, Teacher, Student, Parent) remain completely independent in their UI, layout, components, navigation, and user experience.

Core Product Principle: The system is not designed as "Website + Four Dashboards." It is designed as one complete digital operating system for an educational institution where every major real-world activity has a clear owner, workflow, permission model, data schema, and history: Requirement → User → Permission → Workflow → Data → API → UI.

Institutional Pain Points Solved

The 10 School Problems & EduOS Project Solutions

Direct side-by-side mapping of operational problems to system solutions.

01. Fee Defaulters & Lost Paper Slips Finance

Parents lose paper vouchers; clerks spend hours flipping through paper registers to see who owes money; manual calculation blunders cause revenue loss.

EduOS Solution: Centralized online fee ledger. Prints standardized 3-part bank challans instantly, logs partial payments, calculates arrears automatically, and gives defaulter lists with 1-click.
02. Hidden Bunking & Wasted Class Time Attendance

Calling names from paper registers wastes 15 minutes every period; parents only learn that their child skipped school weeks later via paper letters.

EduOS Solution: 30-second mobile attendance. Default is "Present" (tap only absentees). Instant digital notification sent automatically to parents if child is missing or unexcused.
03. Scattered Student Files Across Cabinets Records

To check marks, guardian phone number, past fees, or medical history, staff must dig through 4 different cupboards across office rooms.

EduOS Solution: 360° Student Profile Dossier. Type any student’s name or roll number to view all 12 operational layers on one single screen.
04. Uncontrolled WhatsApp Chats & Lost Notes Communication

Parents message teachers on personal WhatsApp at 11 PM; important medical leave notes and complaints get buried with zero accountability.

EduOS Solution: Governed Institutional Requests & Ticket System. Leaves and complaints become tracked digital tickets with official statuses, response history, and SLA clocks.
05. Paying Web Developers for Simple Notices Public CMS

Adding a holiday circular, staff update, or event photo to the school website takes days or weeks because the school must pay an outside developer.

EduOS Solution: Built-in Dynamic Website CMS. Admin edits school branding, logo, navigation, theme colors, banners, and circulars directly from the Admin Panel.
06. Handwriting Report Cards & Math Blunders Exams

Teachers spend late nights calculating percentages, positions, and writing report cards by hand; manual math mistakes damage school credibility.

EduOS Solution: Automated Exam & Grading Engine. Teachers enter subject marks once; EduOS calculates GPAs, grading thresholds, and rankings, then generates printable report cards.
07. Waiting Months for Outside ID Card Printers ID Engine

Gathering photos, sending spreadsheets to plastic card printing shops, and fixing misspelled names causes massive delays and extra expenses.

EduOS Solution: Instant Automated ID Card Engine. Official verified cards with institute crest, photo, and QR codes are generated the second admission is approved.
08. Misplaced Paper Leave Applications Leave

Medical leave letters sit on desks and get lost; students get marked absent on the final term sheet, causing angry parent arguments.

EduOS Solution: Integrated Leave Management. Parents apply online; Principal approves with 1-click; daily attendance register automatically updates to "Approved Leave".
09. Parent Login Fatigue for Multiple Children Family

Parents with 2 or 3 children in different classes are forced to log in with 3 different credentials or track three sets of paper diaries.

EduOS Solution: Unified Multi-Child Parent Portal. One parent account connects all siblings with an effortless 1-tap child switcher for attendance, fees, and results.
10. Secret Grade Tampering & Financial Leaks Audit & Security

In paper systems or spreadsheets, anyone can alter an exam score or record a fake fee discount, and leadership has no way of knowing who did it.

EduOS Solution: Immutable System Audit Trail. Records user ID, previous value, new value, IP address, and exact timestamp for complete accountability.
Complete Functional Inventory

The 36 Modules: Complete Granular Breakdown

Every single requirement, field, action, user permission, and data element explicitly specified.

1

Main Portal 1: Public Website & Dynamic CMS (Modules 01 – 03)

Module 01 Public Presence

1. Public Website

The public website represents the institution publicly. Everything visible on the public website should be manageable by Admin without requiring a developer.

Public Content Managed:
  • Homepage
  • About institute
  • Programs / courses
  • Departments
  • Faculty
  • Admissions
  • Events
  • Notices
  • Gallery
  • Facilities
  • Achievements
  • Contact information
  • FAQs
  • Important links
  • Social media links
  • Downloadable documents
  • Admission information
Module 02 Admin Control

2. Dynamic Website Control

Admin should have complete control over the public website via a centralized theme configuration instead of hardcoded colors.

Institute Identity Controls:

Institute name, Logo, Favicon, Description, Contact numbers, Email addresses, Physical address, Social links, Website title, Website description.

Website Appearance Controls:

Primary color, Secondary color, Accent color, Background colors, Text colors, Button styles, Border styles, Theme mode, Light/dark appearance, Fonts, Website branding.

Homepage Section Management:

Hero section, Hero title, Hero description, Hero images, CTA buttons, Featured programs, Featured faculty, Statistics, Notices, Events, Gallery, Testimonials, Section enable/disable toggles.

Navigation & Content Management:

Menu items, labels, order, visibility, footer links. Create, edit, publish, unpublish, and remove public content (basic CMS).

Module 03 Public Visitor

3. Public User & Admissions

Public visitors interact with institutional information and submit inquiries and applications.

Public Visitor Capabilities:
  • Browse the website
  • View institute information, programs, and faculty
  • View public notices, events, and gallery
  • View admission criteria & guidelines
  • Submit online admission application with photo/docs
  • Submit contact messages and inquiries
  • Register as public user
  • Login to public user area
CRITICAL RULE: Public registration does NOT create an academic account.
2

Main Portal 2: Principal & Admin Management Panel

Module 04 Security

4. Authentication & Role Routing

One common login system identifying role and opening correct area:

  • Admin → Admin Panel
  • Teacher → Teacher Panel
  • Student → Student Panel
  • Parent → Parent Panel
  • Public User → Public User Area

Academic accounts created and controlled by Admin; public users register themselves.

Module 05 Admin Only

5. Admin Panel Dashboard

Live Dashboard Includes:

Students, Teachers, Parents, Classes, Admissions, Attendance, Exams, Results, Fees, Applications, Complaints, Notices, Events, Notifications, Recent activity, and Important alerts.

Module 06 Admin Only

6. User Management

Students: Create, View, Edit, Activate/deactivate, Assign class, Assign section, Assign parent, Manage account, View academic info.
Teachers: Create, View, Edit, Activate/deactivate, Assign classes, Assign subjects, Manage account.
Parents: Create, View, Edit, Link children, Manage account, Activate/deactivate.
Public Users: View registered users, Manage status, View relevant information.
Module 07 Admin Only

7. Academic Management

Admin Manages:

Academic sessions, Classes, Sections, Subjects, Class teachers, Subject teachers, Student enrollment, Teacher assignments, Timetable, Academic calendar.

Rule: Structure defines which teacher teaches which subject to which class.

Module 08 Admin & Staff

8. Student Management (360° Profile Dossier)

12 Operational Profile Layers:

1. Personal Info • 2. Parent Info • 3. Class • 4. Subjects • 5. Attendance • 6. Assignments • 7. Exams • 8. Results • 9. Fees • 10. Applications • 11. Complaints • 12. Documents.

Module 12 Admin & Parents

12. Fees & Finance Engine

Fee Structure: Admission fee, Monthly fee, Exam fee, Transport fee, Other charges, Discounts, Scholarships.
Student Fee Management: Generate fees, Assign fees, Due dates, Paid amount, Outstanding amount, Partial payments, Payment history, Receipts, Discounts.
Reports: Daily collection, Monthly collection, Outstanding fees, Paid fees, Student-wise fees, Class-wise fees.
Module 13 Admin Only

13. Admission System

Admission Form → Application → Admin Review → Approve/Reject → Student Creation → Parent Linking → Class Assignment

Admin Can: View applications, Search, Filter, Review, Approve, Reject, Request additional information, Create student, Create/link parent, Assign class.

Module 18 Admin Only

18. Admin / Principal Communication Dispatcher

Receives applications from Teachers, Students, and Parents.

Admin Actions:

Review, Assign to another staff member, Request information, Respond, Approve, Reject, Resolve, Close, Reopen where appropriate, Maintain complete audit history of every application.

Module 21 Leave

21. Leave Management System

Students: Student/Parent submits leave request.

Teachers: Teacher submits leave request to Admin/Principal.

Admin: Reviews & approves/rejects.

Status: Pending, Approved, Rejected, Cancelled.

Approved leave automatically connects with attendance.

Module 22 Notifications

22. Notification System

Triggers:

New admission, Admission approved, New assignment, Deadline, Feedback, Attendance alert, Exam announcement, Result published, Fee reminder, New application, Application response, Complaint update, Notice published.

Targets:

Individual user, Parent, Student, Teacher, Class, Group, Everyone.

Module 24 Schedule

24. Timetable System

Supports conflict-free academic scheduling.

Admin Manages:

Classes, Subjects, Teachers, Rooms where applicable, Days, Time slots.

Views: Teachers see theirs; Students see theirs; Parents see child's.

Module 26 Documents

26. Document Management

Supports Institutional Documents:

Student documents, Teacher documents, Admission documents, Certificates, Notices, Assignment attachments, Result documents.

Strict permission-based access controls.

Module 27 Admin Only

27. Reporting Engine

Admin Reports For:

Students, Teachers, Attendance, Admissions, Fees, Exams, Results, Assignments, Applications, Complaints, Leave, Activities.

Supports multi-filter and useful export/print functionality.

Module 28 Admin Only

28. Audit & Activity History

Important Actions Recorded:

User created, User updated, Account disabled, Fee created, Payment recorded, Result changed, Result published, Attendance modified, Application approved, Complaint resolved, Website content changed.

Provides accountability and forensic investigation.

Module 29 Admin Only

29. Admin Settings

Institute: Name, Logo, Contact, Address, Academic info.

Academic: Session, Grading system, Attendance rules, Fee settings.

Communication: Application categories, Complaint categories, Notification settings, Authorized recipients.

Website: Branding, Colors, Content, Navigation, Homepage, Footer, Public pages.

System: User settings, Permissions, Security settings, Notification settings, Other config.

Module 34 Security

34. Backend Permission Principles

Frontend visibility is not security.

Backend determines: Who can access, create, edit, approve, reject, respond, close, or view sensitive info.

  • Student cannot access another student's data by changing ID in URL.
  • Parent can only access their linked children.
  • Teacher can only access assigned classes/students.
  • Admin has broader institutional access according to permissions.
Module 35 Architecture

35. Complete Central System Flow

Connects Public Website → Authentication → Portals → Central System Data (Attendance, Academics, Finance, Assignments, Exams, Fees, Results, Applications, Notifications) → Communication → Admin / Principal.

Module 36 ID Engine

36. ID Card Management (Student & Teacher)

Generated automatically from information stored in the system without re-entering data.

Student ID Card: Logo, Name, Photo, Student ID, Class, Section, Session, DOB, Parent/Guardian, Contact, Issue date, Expiry date, QR code, Institute contact. Available in Student Panel to View, Download, Print.

Teacher ID Card: Logo, Name, Photo, Teacher ID, Designation, Department, Assigned subjects, Contact, Issue/Expiry date, QR code, Institute contact.

Main Portal 3: Teacher / Faculty Panel (Modules 09, 10, 11, 17, 25, 30)

Module 30 Core Panel

30. Teacher Panel Responsibilities

Teaching + Classes + Students + Attendance + Assignments + Exams + Results + Applications + Communication + Notifications

Teacher must only access assigned academic data.

Module 09 Classroom

9. Attendance System

Teachers record attendance; Admin supervises complete system.

Admin Can: View daily, class, student attendance, Filter by date & class, View attendance %, Correct where authorized, Generate reports.

Students and parents can only view relevant attendance.

Module 10 Coursework

10. Assignments System

Teacher Can: Create assignment, Select class & subject, Add instructions, Add attachments, Set deadline, View submissions, Review submissions, Give marks, Give feedback.

Admin Can: Monitor assignments, View teacher activity, View submissions, Manage where required.

Module 11 Evaluation

11. Exams & Results System

Admin Controls: Exams, Exam types, Schedules, Subjects, Classes, Marks structure, Passing marks, Grading system, Result publication.

Teacher Can: View assigned exams, Enter marks, Edit marks before submission/finalization, Submit marks.

Module 17 Teacher Requests

17. Teacher Applications & Complaints

Submit to: Admin, Principal, Authorized management.

Examples: Leave application, Schedule request, Class-related issue, Student concern, Parent concern, Resource request, Salary/payroll request, Technical issue, General complaint/application.

Teacher Can: Submit, Attach files, Track status, Receive response, Respond to clarifications, View application history.

Module 25 Calendar

25. Calendar & Events

System Calendar Contains:

Academic events, Exams, Holidays, Parent meetings, Events, Important deadlines, Admission dates. Different users see relevant calendar info.

Main Portal 4: Student Panel (Modules 10, 11, 15, 20, 31, 36)

Module 31 Student Core

31. Student Panel Responsibilities

My Education + Attendance + Assignments + Exams + Results + Fees + Applications + Complaints + Notices + Notifications

Students cannot modify protected institutional records.

Module 10 Student Work

Student Assignment Tasks

Student Can:

  • View assignments by subject
  • Download attachments and worksheets
  • Submit completed work online
  • View submission status (submitted / pending)
  • View teacher feedback and marks
Module 11 Student Results

Student Exams & Results

Student Can:

  • View examination schedule and dates
  • Download roll number slip
  • View published results
  • View marks, grades, and cumulative performance
Module 15 Student Desk

15. Student Applications & Complaints

Examples: Leave application, Fee-related request, Academic request, Certificate request, Document request, Class issue, Teacher complaint, General complaint, Personal request.

Submitted → Under Review → Need Info → Approved/Rejected/Resolved

Module 20 Notices

20. Student Notice View

View general notices, student notices, and class-specific notices published by Admin with title, description, attachments, and validity dates.

Module 36 Digital ID

Student ID Card Access

Admission Approved → Account Created → Profile Completed → Photo Available → ID Card Generated → Student Can View/Download/Print

Module 32 Parent Core

32. Parent Panel Responsibilities

My Children + Attendance + Academic Performance + Assignments + Exams + Results + Fees + Applications + Complaints + Communication + Notifications

If parent has multiple children, parent can switch between linked children easily under 1 login.

Module 16 Parent Requests

16. Parent Applications & Complaints

Submit To: Specific teacher where permitted, Class teacher, Relevant department, Admin, Principal.

Examples: Child leave request, Attendance concern, Academic concern, Fee request/issue, Teacher complaint, Child concern, Certificate/document request, Meeting request, General complaint/application.

Parent Can: Submit application, Select child, Select category, Select authorized recipient, Add details, Attach docs, Track status, View responses, Continue communication.

Module 12 Parent Fees

Parent Fee Management

Parent Can:

  • View fee structure & tuition tiers
  • Download monthly bank challans
  • Inspect due dates and paid amounts
  • Review outstanding amount and payment history
  • Download receipts and applied discounts
Module 11 Parent Results

Parent Exams & Results

Parent Can:

  • View child's exam schedule and dates
  • View published term examination results
  • Monitor academic performance, marks, and GPA
  • Download verified report cards
Module 10 Parent Homework

Parent Homework Monitoring

Parent Can:

  • View child's assigned homework tasks
  • Check deadlines and submission status
  • Inspect teacher marks and feedback remarks
Module 09 Parent Attendance

Parent Attendance Tracking

Parent Can:

C

Central Communication, Workflows & Cross-Panel Governance (Modules 14, 19, 20, 23, 33, 35)

Module 14 Central Comms

14. Communication & Application System

Major system-wide feature enabling controlled communication through structured Applications / Requests / Complaints.

Rule: NOT an unrestricted chat system; it is a controlled institutional workflow.

Module 19 Workflow

19. Application Workflow

User creates → Selects child (if parent) → Selects category → Selects authorized recipient → Submit → Teacher/Admin/Principal reviews → Response → Approved/Rejected/Resolved → Notification dispatched

Same workflow applies for Student, Parent, and Teacher applications.

Module 20 Grievance Desk

20. Complaint Management

Contains: Complaint ID, Category, Submitted by, Recipient, Subject, Description, Attachments, Priority, Status, Responses, Resolution, Created date, Updated date, Complete history.

Submitted → Under Review → Assigned → Need Info → In Progress → Resolved → Rejected → Closed

Only authorized staff see sensitive complaints.

Module 23 Notices

23. Notice & Announcement System

Admin Can Create: General notices, Student notices, Parent notices, Teacher notices, Class-specific notices.

Notice Attributes: Title, Description, Attachment, Publish date, Expiry date, Target audience, Status.

Module 33 Bridge

33. Cross-Panel Communication

Connects panels without merging the panels themselves:

  • Student → Application/Complaint → Teacher/Admin
  • Parent → Application/Complaint → Teacher/Admin
  • Teacher → Application/Complaint → Admin/Principal

Every communication strictly follows permissions & institutional rules.

Governance Matrix

Final Responsibility Model

Public Website: Public presence + admissions + info.

Admin: Runs and controls the institution.

Teacher: Teaches & manages assigned academics.

Student: Uses & manages own learning experience.

Parent: Monitors & communicates about children.

Communication: Connects users via controlled requests.

Dynamic CMS: Controls branding without developers.
